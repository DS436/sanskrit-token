# `results/` — a tracked snapshot

This folder exists so that the numbers in this repository can be read **without running
anything**. It is a copy, not a source: each experiment writes its real output to
`outputs/<experiment>/`, which is gitignored, and what is committed here is the
`results.json`, the `config.yaml` that produced it, and the figures, taken from the run
each experiment's own `README.md` reports.

Nothing here is generated by a script at commit time. If you re-run an experiment (see the
**Reproduce** section of the root `README.md`) it writes to `outputs/`, leaving this
snapshot untouched, and you can diff the two.

Those fields are read straight out of each `results.json`, where every experiment records
the commit it ran at and whether the working tree was clean. Experiment 01's run was made
with a dirty tree, which is recorded rather than hidden; Experiments 02–05 were re-run at a
clean tree after the review waves their READMEs describe.

The commits above are **the runs' commits, not this snapshot's commit**. They differ
because each experiment was re-run at the moment its last correction landed, and the
snapshot was assembled later.

## What is *not* here

- Model checkpoints, encoded token streams (`outputs/05_lm_training/encoded/`, ~3.5 GB) and
  trained tokenizer files (`outputs/tokenizers/`, 84 MB). Too large, and all derived.
- Raw and processed corpora. No corpus text, raw or derived, is distributed in this
  repository — see `data/README.md` for where each source comes from and under what licence.
- Run logs. They stay in `outputs/`.

The whole folder is ~2 MB.
